# 途泊智能体课堂助教 · 数据库设计

> 版本：V21 配置模式落地后整理
> 字段类型采用通用写法（`string` / `int` / `float` / `json` / `text` / `datetime` / `boolean` / `enum`），可映射到 SQLite / MySQL / PostgreSQL 任意一种。

---

## 一、总体数据分层

```
持久存储（配置 + 素材）
  ├─ course 课程 ──< page 页面 ──< module 页面模块
  └─ material 素材（图 / 视频）

临时存储（课堂运行期）
  └─ class_session 课堂场次 ──< interaction_session 交互活动 ──< 各类型作答明细
                                      │
                                      └─ 学生作答 → 词云 / 选择题 / 图片 / 抽签 / 平台交互 / 实验
```

- **配置数据、素材数据**：一次配置、反复使用，永久落库。
- **交互模块数据**：每次上课（一个「课堂场次」）产生的过程数据，随场次结束可归档或清空。

---

## 二、配置数据（持久存储）

### 1. 课程表 `course`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| name | string | 课程名称，如「多约束条件下的数字调制设计」 |
| code | string | 课程编码（可选） |
| description | text | 课程简介（可选） |
| cover_url | string | 封面图（可选） |
| created_at / updated_at | datetime | 时间戳 |

### 2. 页面表 `page`（一页 PPT）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| course_id | string | 外键 → course.id |
| order_index | int | 页码序号（决定放映顺序，支持拖拽换序） |
| title | string | 页面标题（可重命名） |
| note | text | 讲稿 / 备注（可选） |
| created_at / updated_at | datetime | 时间戳 |

### 3. 页面模块表 `module`（一页 PPT 里的一个「模块」）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| page_id | string | 外键 → page.id |
| order_index | int | 同页模块叠放层级（可选） |
| type | enum | `media` / `text` / `wordcloud` / `choice` / `image_upload` / `lottery` / `platform_interaction` / `experiment` |
| name | string | 模块名（展示用） |
| x / y / w / h | float(0–100) | 百分比位置与尺寸 |
| style | json | 文本样式 `{ fontFamily, fontSize, fontWeight, color }` |
| config | json | **类型专属配置**，见下 |
| created_at / updated_at | datetime | 时间戳 |

`config` 按 `type` 取值（多态，用 JSON 承载最灵活）：

| type | config 内容 |
|---|---|
| media | `{ material_id, caption }` |
| text | `{ content }` |
| wordcloud | `{ question, max_words, min_length }` |
| choice | `{ question, options[], correct_index, is_multiple }` |
| image_upload | `{ prompt, max_size, allow_photo }` |
| lottery | `{ roster[], mode }`（mode：顺序 / 随机 / 不重复） |
| platform_interaction | `{ interaction_key, params }`（待定） |
| experiment | `{ experiment_id, params }`（待定） |

> 约定：`style` 只放**文本排版**，`config` 放**模块业务配置**，位置尺寸单独成列，避免把「位置」混进业务 JSON。

## 三、素材数据（持久存储）

### 4. 素材表 `material`（图片 / 视频）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| name | string | 素材名称 |
| type | enum | `image` / `video` |
| file_url | string | 文件路径（相对路径，离线包内） |
| poster_url | string | 视频封面图路径（image 可空） |
| mime_type | string | `image/png`、`video/mp4` 等 |
| size | int | 字节数 |
| width / height | int | 图片尺寸（视频可空） |
| duration | float | 视频时长秒（图片可空） |
| tags | json | 标签数组（可选） |
| created_at / updated_at | datetime | 时间戳 |

> 当前实现里的 `MATERIALS`（8 个固定素材）即本表的种子数据。

## 四、交互模块数据（临时存储）

### 5. 学生表 `student`（名单，半持久）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| name | string | 姓名（如「孙鹏祺」） |
| student_no | string | 学号 |
| group | string | 分组（如「第1组」） |
| class_name | string | 班级（可选） |

### 6. 课堂场次表 `class_session`（临时数据的归属容器）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| course_id | string | 外键 → course.id |
| teacher_id / room | string | 教师 / 教室（可选） |
| started_at / ended_at | datetime | 上下课时间 |
| status | enum | `ongoing` / `ended` / `archived` |

> 所有交互数据都挂在某个「场次」下，场次结束即可清空或归档——这就是「临时存储」的边界。

### 7. 交互活动表 `interaction_session`（每个交互模块开启后产生一条）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string(uuid) | 主键 |
| class_session_id | string | 外键 → class_session.id |
| course_id / page_id / module_id | string | 定位外键（module_id 关联配置模块） |
| type | enum | 同 module.type 的交互类型 |
| title | string | 活动标题（快照） |
| config_snapshot | json | 开启时的配置快照（question、options 等） |
| status | enum | `pending` / `active` / `closed` |
| started_at / ended_at | datetime | 起止时间 |

### 8. 各类型作答明细（按 type 分表）

#### 8-1 词云作答 `wordcloud_answer`（需求 1：文字问题作答、生成词云）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| session_id | string | 外键 → interaction_session.id |
| student_id | string | 外键 → student.id |
| answer | text | 学生原始作答文字 |
| words | json | 分词结果 `["实时视频","位置数据"]`（后端分词时存） |
| submitted_at | datetime | 提交时间 |

> 词频可另缓存一张 `wordcloud_word(session_id, word, count)`，也可由前端对 answer 实时统计、不落库。

#### 8-2 选择题作答 `choice_answer`（需求 2：选择题问题作答）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| session_id / student_id | string | 外键 |
| option_index | int | 所选选项索引（0–3） |
| is_correct | boolean | 是否答对（可计算，冗余存储便于统计） |
| submitted_at | datetime | 提交时间 |

#### 8-3 图片上传 `image_upload`（需求 3：图片上传 / 学生手写拍照）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| session_id / student_id | string | 外键 |
| file_url | string | 图片路径 |
| mime_type / size | string / int | 类型与大小 |
| submitted_at | datetime | 提交时间 |

#### 8-4 随机抽签 `lottery_draw`（需求 4：随机抽签）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| session_id / student_id | string | 外键 |
| draw_order | int | 第几个被抽中 |
| drawn_at | datetime | 抽中时间 |

> 抽签「池」（候选人名单）来自 `module.config.roster` 或 `student` 表，抽签只记录「谁被抽中、顺序」。

#### 8-5 平台交互结果 `platform_interaction_result`（需求 5：待定，如拖拽调整星座图）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| session_id / student_id | string | 外键 |
| interaction_key | string | 交互类型键（如 `constellation_drag`） |
| result_data | json | 交互结果（如星座点坐标序列） |
| submitted_at | datetime | 提交时间 |

#### 8-6 实验记录 `experiment_result`（需求 6：实验，待定）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 主键 |
| session_id / student_id | string | 外键 |
| experiment_id | string | 实验任务 ID |
| result_data | json | 实验结果（如星座图收发数据） |
| score | float | 评分（可选） |
| status | enum | `running` / `submitted` / `graded` |
| submitted_at | datetime | 提交时间 |

## 五、与现有实现（localStorage）的映射

现在 Demo 里 `localStorage['tubo-config-courses']` 存的扁平结构，展开后对应上面三张配置表：

| 现有 localStorage 字段 | 对应表 / 列 |
|---|---|
| `courses[].id / name` | `course.id / name` |
| `courses[].pages[].id / title` | `page.id / title`（`order_index` = 数组下标） |
| `pages[].modules[].type / name / x / y / w / h / style` | `module.type / name / x / y / w / h / style` |
| `modules[].src / poster / question / options / prompt / text` | 迁移到 `module.config` JSON |

固定 8 个 `MATERIALS` → `material` 表的种子数据；词云 / 选择题 / 手写题的「已作答 N / 24」是 `*_answer` 明细表的 `COUNT`。

## 六、说明与待定项

- **多态 `module.config`**：当前用 JSON 承载各类型配置，实现最简单；若后续要求严格三范式，可拆为 `module_media` / `module_choice` 等独立子表（`config` 展开为列）。
- **待定类型**：`platform_interaction`（需求 5）与 `experiment`（需求 6）目前仅预留 `type` 枚举与 `config` / `result_data` 通用结构，具体字段待需求细化后补充。
- **投屏 / 统计**：均是对上述明细表的**只读查询**（按 `session_id` 聚合），不另设表。
